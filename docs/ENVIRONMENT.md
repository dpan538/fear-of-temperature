# Python, Jupyter and VS Code environment

## Supported profile

- Python: 3.12 only (`.python-version`; validated root environment 3.12.13; bootstrap also installed uv-managed 3.12.14 for future rebuilds)
- Package manager: uv 0.12.13
- Project environment: root `.venv`
- Locked dependency graph: `uv.lock` (208 resolved packages; 189 installed in the full profile)
- Kernel name: `fear-of-temperature`
- Kernel display name: `Python (Fear of Temperature)`
- VS Code interpreter: `${workspaceFolder}/.venv/bin/python`

Python 3.12 was selected because the installed system default was Python 3.13 while the PyTorch macOS installation guidance recommends Python 3.9–3.12. The project does not install a CUDA build on Apple Silicon.

## Bootstrap and exact rebuild

```bash
./scripts/bootstrap.sh
```

The script:

1. keeps uv's cache and managed-Python directories under the project `.cache/`;
2. creates `.env` from `.env.example` only when `.env` is absent;
3. performs `uv sync --locked --all-extras --group dev` into root `.venv`;
4. downloads and runs each configured model once;
5. registers the project kernel;
6. runs the offline synthetic end-to-end demo; and
7. runs the full doctor, including cached-model inference.

It never deletes an existing environment or overwrites an existing `.env`.

For an exact manual rebuild:

```bash
UV_CACHE_DIR="$PWD/.cache/uv" \
UV_PYTHON_INSTALL_DIR="$PWD/.cache/uv/python" \
UV_PYTHON_BIN_DIR="$PWD/.cache/uv/bin" \
uv sync --locked --all-extras --group dev --python 3.12
```

`pyproject.toml` is authoritative. `requirements.txt` delegates to `.[legacy]` so old proposal/report installation commands still work without maintaining a second version list.

## Kernel maintenance

Register or refresh the kernel after recreating `.venv`:

```bash
./scripts/register_kernel.sh
```

Inspect and remove it:

```bash
.venv/bin/jupyter kernelspec list --json
.venv/bin/jupyter kernelspec uninstall fear-of-temperature
```

The verified kernelspec `argv[0]` and notebook kernel process both point to:

```text
/Users/jarlgiovanni/Desktop/fear_of_temperature/.venv/bin/python
```

That absolute path is unavoidable in a user-level kernelspec and is regenerated by the portable registration script. No personal absolute path is stored in `.vscode/` or notebook metadata.

`.vscode/settings.json` configures the interpreter, `.env`, pytest, Ruff, source analysis, notebook root and search exclusions. Tasks cover bootstrap, doctor, tests, demo, notebooks, figures and the legacy validation. `launch.json` provides debug entries for the demo and doctor.

## Device selection and fallback

Set `FOT_DEVICE=auto`, `mps` or `cpu` in `.env`.

- `auto` performs a real MPS tensor operation before selecting it.
- `mps` falls back to CPU if the backend is unavailable.
- model transfer or inference failures on MPS are caught and retried on CPU;
- the requested device, actual device and fallback reason are written to the demo manifest and model registry.

On the validated Apple M1, PyTorch 2.14.0 reported MPS built and available, the tensor probe returned 8.0, and both Transformer models completed inference on MPS with no fallback. Sandboxed shells may hide MPS; the final hardware validation and notebook execution used the normal local kernel context.

`PYTORCH_ENABLE_MPS_FALLBACK=1` is set in `.env.example` for unsupported individual operators. `LOKY_MAX_CPU_COUNT=8` prevents joblib from probing restricted macOS `sysctl` fields.

## Models and offline execution

The first bootstrap downloads fixed snapshots into `.cache/huggingface`. Thereafter:

```bash
.venv/bin/fear-temperature-demo --offline
.venv/bin/fear-temperature-doctor --full-models
```

Offline mode resolves the exact cached snapshot directory before library loading, so it performs no Hub metadata request. No model enables remote custom code.

## Common failures

- **`uv` cannot write `~/.cache/uv`:** use the project-local `UV_CACHE_DIR` commands above; the bootstrap already does this.
- **Model missing in offline mode:** run `.venv/bin/python scripts/download_models.py` once with network access.
- **Wrong notebook interpreter:** choose `Python (Fear of Temperature)` and verify `sys.executable` ends in `fear_of_temperature/.venv/bin/python`.
- **Kernel points to a deleted environment:** recreate `.venv`, then rerun `./scripts/register_kernel.sh`.
- **MPS unavailable:** run with `FOT_DEVICE=cpu`; outputs record the fallback rather than claiming GPU use.
- **Raw data or cache overwhelms VS Code search:** the relevant directories are already excluded in `.vscode/settings.json`.
- **PostgreSQL is unavailable:** the demo uses local DuckDB. PostgreSQL remains optional and no existing instance or migration is modified by bootstrap.
