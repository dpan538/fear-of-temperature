# 数据库试点进度报告

## 本轮完成

- 沿用现有 DuckDB 存储路线，没有建立平行工程。
- 从 M1.1 保存的真实 Content API 元数据导入 9 个唯一文档、9 个原始记录、6 个机构和 14 条文档—机构关系。
- 将首次发布日期、更新时间和采集时间分别存储；时间筛选依据明确为 Content API `first_published_at`。
- 建立来源、采集批次、覆盖分母、原始记录、规范化文档、规范化版本及其追溯关系。
- 建立但不填充段落、声音归因和文档关系接口；没有采集或伪造正文。
- 实现重复导入、干净重建、逻辑指纹、CSV 导出、字段字典和数据质量报告。
- 用隔离的内存测试验证原始载荷变化和规则版本变化会产生文档版本记录。

## 主要发现

- 9 个文档仍是 9 个文档；3 个多机构文档形成 14 条机构关系。完整权重合计 14，分数权重合计 9。
- 9 条首次发布日期均存在且位于 2026 年 7 月；更新日期没有被误用作发布日期。
- 当前证据可以支持一个严格限定的 metadata database pilot，但不能支持正文切段、向量化或历史覆盖主张。
- 项目材料没有提供可核验的 ethics approval/exemption；正文与衍生数据库的审批/豁免路径仍是阻塞点。

## 仍未解决的归一化问题

- 多机构文档在正式分机构统计中使用完整计数、lead-only 还是分数计数，尚未批准；本轮只同时保存可审计权重。
- GOV.UK lead/emphasised organisation 字段的稳定性尚未核验。
- 跨来源重复、镜像、引用和内容重叠没有正文与第二来源，状态保持 `unknown`。
- 1988–2026 的历史渠道变化、回填、撤稿、类型漂移和覆盖起点没有证据。
- 政策/媒体/公众的共同字段契约已留接口，但 media/public 尚无已批准数据，不做跨角色可比性主张。
- 公众材料将来必须把主帖、评论、引用和转发分开；当前仅由 `unit_type`、父项和关系接口预留。

## 下一步最小任务

不扩大窗口、不抓取新来源。先取得并记录导师/伦理路线与逐项正文/附件权利决定；若允许，只选择现有 9 条中的最多 3 条，对 landing page/attachment 的正文单位与定位方式做 metadata-to-paragraph provenance 验证。若许可或伦理条件仍未解决，则改做同一元数据批次的周际/版本稳定性复查，不采集正文。

完成上述 gate 前，不进行向量化、模型训练、情绪分类、语义分析或时间序列分析。
