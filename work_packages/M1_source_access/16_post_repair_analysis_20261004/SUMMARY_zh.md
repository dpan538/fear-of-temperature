# 修复后当前状态与下一步

核查时间：**2026年10月4日22:21（中国标准时间）**。研究发表区间仍为 **1988-01-01至2026-09-21**，2026年9月不完整。本轮完成交接分析，没有启动下载或写入正式数据库。

英国修复 release 与现有数据库的大小、mtime 检查点一致。一次只读元数据汇总确认 **248,319个有效来源内父文档**，比历史表多284个：202个来自已保存ZIP的恢复，82个来自已保存HTML的重新拆分。1,256个既有父文档投影、6,852段文本的修复沿用已提交验收证据，没有重跑。

月度计数只改变了Historic Hansard书面答复的 **9个月**。六个月增加284个本地恢复/拆分父文档；2003年6月减51、7月减73，10月加73。51条保留 **2002-12-20至2003-01-06** 区间，不强行放入某月；73条支持2003年10月，但没有确定日。可归入单月的英国父文档为 **248,268**，支持确定日的为 **248,195**。月份变化净增233，再加51条跨月记录，与总量净增284对齐。旧 **465/465** 是历史有文本文献月份快照，本轮未重新计算。

英国来源内库存仍高度依赖议会答复：含ParlParse镜像的答复占 **98.47%**；官方三条答复路线合计236,108个父文档。镜像、共同答复与附件不能直接加成独立发言总数。修复改善了结构和日期，没有改变这种来源构成。

剩余 **318项问题实例对应165个单位**：153个EU Work贡献306条成对问题，9个英国单位有角色/映射问题，3个澳洲单位涉及日期或作者—托管者—出版者区别。另有37个HTML验证器适配限制，不能把它们再加成37项缺失原件。56,271条历史“不可核查”注释也不转成下载队列。来源身份核验不证明正文每个主张真实。

最终原件请求是 **5项：3项Hansard section原件＋2项澳洲发表日期/主文件证据**。旧Task4的3项API路线使用贡献ID，必须由最终manifest里的section ExtId取代；正确section API曾HTTP400，应使用有依据的替代原件路线，不能盲目重试。两项澳洲CMS日期都不能代替发表日，其中9月22日的CMS时间也不能单独判定超期。此前撤回的EU请求已有保存字节，不恢复下载。

EU2015计划仍是 **1,009个已枚举Work中的979个候选Item**，30个无链接，覆盖全年12个月，尚未新增原件。它有望增加委员会行政出版文本深度，但不能宣称已经减少偏差。**973个Work有多个Item备选；其中253个在选中的同一PDF Manifestation内就有多个Item**，因此单PDF下载成功不等于完整Work或完整附件。其余726个单Item也尚未证明完整。建议保留979项冻结选择，分别记录候选字节、可读Item、身份/日期和Work组成完整性；不自动扩展为下载所有备选。

本轮发现一个可复现的执行障碍：**真实release有效，但现有下载脚本不识别它的字段格式**。脚本寻找“before/after”和独立committed/checked键，实际release使用“pre/post”和明确状态字符串。离线预检因此失败。脚本还没有强制检查最终5项A请求的结案记录。当前约 **20.67 GiB** 可用，按原有预留计算剩余约17.51 GiB，存储预检通过；真正执行前仍需重新测量。

推荐下一步：**先修正并离线验证下载器兼容性，登记5项原件请求的有界结果，再执行同一979项EU候选字节队列**。保留2 GiB新增原始数据上限、15 GiB磁盘底线、串行请求、限速和失败停止规则。完整Work判定及正式入库交给后续单写入者，不能把候选字节当作完整可读父文档。已有项目采集许可和修复release继续有效；本轮初始交接任务只提交分析与执行建议。
