# 英国议会答复父记录结构校验摘要

本任务只读检查 06 DuckDB 中登记的英国议会书面答复/声明父记录及其保存的 XML、JSON、HTML 原文，发表日期范围固定为 **1988-01-01 至 2026-09-21**。未改数据库、原始文件或冻结报告，也未按气候相关性、情绪或恐惧筛选。

| 结果 | 父记录数 |
| --- | ---: |
| 原文分组与子段落结构通过 | 239,546 |
| 原 API 明示联答且答案文本一致 | 6,044 |
| 需核查的边界冲突 | 1,381 |
| 证据不足 | 9 |
| **合计** | **246,980** |

实际读取并解析了 **27,124 / 27,127** 个已关联的保存容器；另外三个 Hansard 列表 JSON 缺少详情页 `Overview` 结构。全量只读通过一次，随后仅针对首轮异常容器和少量日期/HTML 样本复核。十个针对真实缺块、跨父记录、共享答复及日期歧义的测试通过。`INPUT_MANIFEST.json` 记录数据库检查点、读取范围和每次互斥锁占用时间。

主要待办：Hansard 详情 1,113 条边界冲突，多为原文 `ERR_Question` 被存为答复；1991 年 Historic 单项 HTML 有 135 条分组/段落冲突；Historic XML 有 124 条 2003 年日期落在原文范围标题之外，另有 7 条角色交叉和 2 条答复段落缺失。五个 Historic ZIP 中 202 个有 ID 的原文分组未在同源数据库中登记，但仍须先查旧排除和重叠记录，不能直接补采。ParlParse 镜像内部的 8,448 条分组均通过本次结构检查；这不证明它与官方版本逐字等同。

无段落 ID 的 Historic XML 中，58,937 条通过唯一、完全一致的问答文本定位到原文分组；父 ID 的哈希未独立重算。现代 API 的 6,044 条共享答复属于明示联答，不应作重复导入。另有 6,287 个联答关系簇文本不同或不完整，只是答复组层面的待核查状态，不使各父记录自动失败。

交接文件：`REPORT.md`（方法、局限和待办）、`exceptions.csv`（父记录及原文定位）、`omission_reconciliation.csv`（202 个候选遗漏）、`answer_groups.csv`（联答组）、`parent_results.csv`、`container_results.csv`、`execution_coverage.csv` 和 `RESULT.json`。后续修复/补采须由协调任务根据两项结构校验结果另定范围；本任务没有启动下游任务。
