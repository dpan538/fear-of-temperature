```bash

```

Repeat bounded fetch and ingest commands until the selected series is complete or an official endpoint stops ordinary access. `--limit` counts new attempts or new versions, not already verified downloads. A saved 2xx object is reused only after its SHA-256 matches the request checkpoint. Failed HTTP responses and transport errors have JSON checkpoints and, when received, short error bodies. Never bypass a 403, challenge or 429; honour `Retry-After` before a later retry. The US route uses the official `raw_text_url` pattern from the document API and embeds the publication date to avoid two known document-number collisions. Ordinary HTML pages returned an access page in this runtime; no bypass was attempted.

An HTTP 404/410 raw-text checkpoint is retained as an unavailable object and skipped in later blocks, so it cannot monopolise the request window. Its parent remains missing a body until a separately verified fallback is ingested. Transient failures remain eligible for a later ordinary retry; access-limit responses stop the current supervisor cycle.

For the 19 March 2000 raw-text 404s, `us_govinfo_fallback.py` stages the corresponding official GovInfo `/html/<FR Doc>.htm` originals without replacing the failed FederalRegister.gov checkpoints. `audit_us_govinfo_fallback.py` rehashes each HTML file and checks a single document `<pre>` block, matching FR Doc number in both header and footer. `acquire.py ingest-us` accepts a verified fallback version under the existing parent/content object, extracts the original `<pre>` text and keeps the HTML byte hash and URL as the content version. This stage may run while the US supervisor is active, but ingestion must remain with its single database writer. A raw-text 404 is a route exception, not a missing body once its GovInfo fallback version is inserted.

For unattended completion of the already frozen US series, after any active writer/network block has stopped, run one supervisor:

```bash
.venv/bin/python work_packages/M1_source_access/09_us_au_government_acquisition/run_us_remaining.py
```

It holds a single-process lock, alternates one rate-spaced fetch block and one committed ingestion block, updates `checkpoints/supervisor_state.json`, `checkpoints/batch_progress.jsonl` and `checkpoints/supervisor.log`, and stops on access errors, no progress or less than 15 GB free disk. This floor leaves room for the next raw block, DuckDB transaction and EU/OCR temporary files on the shared volume. Each block records new downloads and new ingested parents plus the target/download/version ordering check. Full reports, audits and Figure 5 run at selected-series completion or a no-progress stop without an access limit. It does not touch AU or expand the filter.
The US ingestion path groups at most 25 new parents in one DuckDB transaction and prints each 25-parent milestone only after its commit. A crash can roll back the active group while leaving previously committed groups and verified raw files intact; rerunning ingestion reconciles from content-version IDs. The source supervisor still audits target/download/insert ordering after its block.
When the stopped supervisor has a recent HTTP 429, `us_polite_resume.py --dry-run` displays the specific failed request and earliest ordinary retry time. Running the script without `--dry-run` waits at least one hour from that response and longer if a server `Retry-After` requires it, launches exactly one single-writer supervisor, and repeats only for a new evidenced 429. It stops after three 429s on the same raw-text object, any different failure, a storage stop, or a nonzero supervisor exit. Do not run a separate supervisor while the wrapper is active. The 27 September 05:18 UTC 429 on `2007-02-27/E7-3311.txt` had no `Retry-After` and was followed by successful ingestion of the other 407 files in its block; the first eligible retry is 06:18 UTC.
Run the wrapper with the same network permission as the source downloader. A 06:18 UTC wrapper launched in the restricted default sandbox produced three local DNS `NameResolutionError` checkpoints without reaching the source, then stopped because the failure was not HTTP 429. A network-enabled supervisor retried `E7-3311.txt` at 06:19 UTC and received a verified HTTP 200; the original 429 and local DNS failures remain in that object's `.attempts.jsonl`. ## Outputs and checks

After the bounded source queues have completed or reached evidenced external barriers, refresh `report.py`, `audit.py`, EU byte/Work/WEMI audits, `eu_disposition_ledger.py`, and `eu_report.py` on the committed snapshot. Then run `consolidated_coverage.py` and `figure5_cross_source.py`. The cross-source Figure 5 reads only the consolidated monthly CSV and records that file's SHA-256 in its QA JSON; the source-specific 09 `figure5.py` remains available separately. A non-final smoke plot must not be presented as completed coverage.

- `raw/us_fr/` and `raw/au_landing/`: original bytes with `.request.json` checkpoints.
- `reports/object_status.csv`: all unique target records and current request state.
- `reports/exceptions.csv`: attempted failures, including status and reason.
- `reports/success_records.csv`, `extraction_exceptions.csv`, `pending_records.csv`: separated cleaned successes, no-text/OCR/unsupported outcomes and unrequested targets.
- `reports/monthly_progress.csv`: source, agency, genre and month, including unsupported US years and unresolved AU dates.
- `reports/quality_metrics.json`: version, segment, orphan and date-precision checks.
- `FILTER_CONTRACT.md`: frozen source filters and record boundaries.

Only verified downloaded bytes create `content_versions`. `source_extracted` and `cleaned` segments point to the exact content version and different extraction runs. Original bytes and source line/page locators remain available. The `us_au_record_evidence` table preserves AU precision and CMS timestamp separately; `us_au_fetch_evidence` holds successful request details. The UK database is never opened for writing by these commands.

The first US ingestion block used `us_au_source_extract_v1` (one source segment per printed line). To keep the 33,544-record series within the available storage while preserving original bytes and clean-to-source maps, later US blocks use `us_fr_whole_source_extract_v2`: one complete source-text segment per document plus cleaned paragraphs with original line ranges. Existing v1 segments remain immutable. Parent counts are unaffected by this extraction representation change.
